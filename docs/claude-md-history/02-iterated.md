# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project context
Transparent plant care app (course project P3). It predicts watering *before* a plant shows stress, from a
published-science model, and always shows **why** with the numbers, as a range ("water in 3–5 days").
Owners manage plants; sitters only see today's tasks for shared plants.

- Product requirements, roles and user stories: @docs/PRD.md
- Model equations, constants and citations: @docs/model-science.md
- Next.js version notes (auto-maintained by `next dev`): @AGENTS.md

## Tech stack
- **Next.js 16** App Router in `src/app/`, React 19, TypeScript `strict`, Tailwind CSS v4.
- **Postgres** (planned, via Vercel Postgres/Neon) and **Auth.js** for owner/sitter roles — not wired yet.
- **Claude Agent SDK** agent (story 6) that calls model functions as tools; it must never compute advice itself.
- **Testing:** Vitest (node env), fast-check property tests, Stryker mutation testing.
- Deploy target: Vercel.
- Local Node lives at `~/.local/node/bin` (no system Node). Prefix shell commands with
  `export PATH=~/.local/node/bin:$PATH`.

## Commands
- `npm run dev` / `npm run build` / `npm run lint` / `npm run typecheck`
- `npm test` — all tests once; `npx vitest run src/lib/model/vpd.test.ts -t "name"` for one test
- `npm run coverage` — V8 coverage for `src/lib/**`
- `npm run mutate` — Stryker over `src/lib/model/**`; build breaks below 75 % mutation score

## Architecture decisions
1. **The model is pure functions** in `src/lib/model/` — no I/O, no `Date.now()`, no React, no DB. Inputs
   in, numbers out. This is what makes it TDD-able, property-testable and reusable as agent tools.
2. **Predictions are ranges, never single dates.** `predictWatering` returns `{ earliestDays, latestDays }`
   plus the intermediate factors (VPD, DLI, budget, daily loss) so the UI and the agent can explain it.
3. **Explanations are derived, not written.** `src/lib/explain/` turns model factors into plain-language
   sentences; UI and agent render those, they do not re-derive numbers.
4. **Server components fetch, model computes, client components render.** Data access (Postgres) will live in
   `src/lib/db/` and is the only layer allowed to do I/O.
5. **Units in names**: `tempC`, `rhPct`, `potDiameterCm`, `lossLPerDay`, `dli` (mol·m⁻²·d⁻¹), `vpdKPa`.

## Coding conventions
- Named exports only; one concept per file; file names kebab-case (`predict-watering.ts`).
- Validate inputs at model boundaries and throw `RangeError` with the parameter name in the message.
- Every science constant is a named `const` with a comment citing `docs/model-science.md`.
- Tests sit next to code: `foo.ts` ↔ `foo.test.ts`. Prefer `toBeCloseTo` for floats.
- Commit messages: Conventional Commits. TDD commits use `test(scope): red — …`, `feat(scope): green — …`,
  `refactor(scope): …`.

## Testing strategy
- **Strict TDD for `src/lib/**`:** write a failing test, commit it (red), write the minimum code to pass
  (green), commit, then refactor with tests green. One acceptance criterion per cycle.
- **Example tests** pin reference values from `docs/model-science.md` (e.g. SVP(20 °C) ≈ 2.338 kPa).
- **Property tests (fast-check)** pin monotonicity: higher VPD or light ⇒ never later watering; bigger pot
  or more retentive soil ⇒ never sooner; `earliestDays ≤ latestDays` and both ≥ 1.
- **Mutation testing (Stryker)** on the model before merging model changes.
- UI is checked by running the app; no snapshot tests.

## Do
- Read the relevant guide in `node_modules/next/dist/docs/` before writing routes or server components
  (Next 16 + `cacheComponents` differ from older Next.js).
- Run `npm test && npm run typecheck && npm run lint` before every commit.
- Keep commits small and phase-labelled so the history shows Explore→Plan→Implement→Commit and red/green/refactor.
- Use Plan mode for anything touching more than two files.

## Don't
- Don't put model maths in components, route handlers or agent prompts.
- Don't show a single watering date or a number without its "why".
- Don't add plant-ID-from-photo or smart-sensor features (out of scope).
- Don't write implementation code before its failing test exists in `src/lib/**`.
- Don't edit `AGENTS.md` by hand (regenerated by `next dev`), `.env*`, or `package-lock.json` directly.

## Context management
- `/clear` between unrelated tasks (e.g. after finishing a TDD cycle set, before starting a UI feature).
- `/compact Keep: current acceptance criterion, failing test name, files touched` when a long TDD session nears the limit.
- `claude --continue` to resume the last session after a break instead of re-explaining.
- Long-lived knowledge goes in this file or `docs/`, not in chat.
